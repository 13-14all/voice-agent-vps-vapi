PROJECT LEDGER v1 — Effective 2026-08-28

## 1️⃣ Vision
Build a multi-tenant AI voice agent that can place and receive phone calls on
behalf of several small businesses plus a personal use case, all routed by
the phone number or assistant dialed. This repo is the Vapi.ai-specific
sibling of voice-agent-vps (Retell edition): telephony/STT/TTS/turn-taking
run on Vapi, and this VPS hosts only the conversation brain (an
OpenAI-compatible Custom LLM endpoint), per-business knowledge, and the
training loops. The system keeps learning from three sources: uploaded
business knowledge, simulated agent-vs-agent calls, and real live callers
(via Vapi's `end-of-call-report` webhook).

## 2️⃣ Architecture
- Telephony/STT/TTS/turn-taking: Vapi.ai (managed or Twilio-imported numbers)
- Brain: FastAPI OpenAI-compatible endpoint (`POST /vapi/chat/completions`)
- LLM: hybrid router — local Ollama (llama3:8b) for simple turns, cloud
  model (GPT-5 class) for complex reasoning/booking logic
- Knowledge: Postgres + pgvector, one `knowledge_chunks` table, isolated by
  `namespace` per business, retrieved via RAG into the prompt every turn
- Post-call: Vapi `end-of-call-report` webhook -> our own scorecard -> flag
  for review -> human-approved corrections fold back into knowledge + scenarios
- Provisioning: `app/vapi/provision.py` creates/updates one Vapi Assistant
  per business from `config/businesses/*.yaml`, all pointing at the same
  Custom LLM endpoint
- Two routing modes supported: static (one assistant+number per business,
  keyed by call.assistantId) and dynamic (`assistant-request` webhook,
  keyed by dialed number — for the "many forwarded numbers, one Vapi
  number" pattern)
Full detail: docs/ARCHITECTURE.md
